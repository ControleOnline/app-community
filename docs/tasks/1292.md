# Task 1292 — Manager themes, media and order indicators

https://github.com/ControleOnline/app-community/issues/1292

Approved palettes live in docs/themes/{manager,lave-go}/{light,dark}.json. All component colors use canonical object tokens from docs/themes/themes-map.md. Explicit domain/API assignments live in docs/themes/domain-profiles.json; profiles replace the entire palette and never fill missing tokens from another tenant. Dev/dd and staging/s select Manager. Lave-Go/apinew selects its own palette and paid-order value. The production Manager domain is unchanged. Loopback retains local evaluation; query parameters are unnecessary.

This delivery versions theme configuration as JSON data in the app. It does not write production Theme.colors or introduce database columns. Persisting the two modes in production is a separate, explicit rollout. Domain profiles are assignments, not fallback colors, and cannot activate on a mismatched API or published host.

Order summaries are supplied by a stable controleonline/orders package. No edited vendor files or local report-routing configuration is required on published sites. Existing sale/closed value remains the default. Paid/open value is explicitly assigned to the service domain; no inference from the current order rows, status mutation or receipt calculation. Movement counts the same collection as the Pedidos card.

Scope also includes proportional company media, readable responsive full company names, selected-option contrast, semantic AppTypeSwitcher tokens, login identifier and loopback domain resolution. The existing reproducible npm patch mechanism validates exact input before applying; it never silently patches an incompatible package.

Publication: task branches → merge dev → Security → frozen RC → staging → In Review. No master or production deployment authorized.
